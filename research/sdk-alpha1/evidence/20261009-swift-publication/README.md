# Swift registered publication component

Both Debug and Release execute 60 named Swift tests with warnings as errors and
complete concurrency checking. The public `ContinuityDevice` API prepares and
recovers the original QPPUBA01 artifact through the existing registered owner.
Real separate-process runs perform registration, publication/status/retry,
cancellation of an unallocated next ID, retirement, and subsequent ordinary
TLS/application traffic. The native authority harness verifies all manifest
signatures and membership proofs. Eighty-five public records per profile are
independently reread and retained in CAPTURES.zip.

The first runtime probe refused a missing expected-library identity. The second
refused the actual loaded path: the development dylib retained an absolute Cargo
install name. Isolated copies were given an @rpath install name and an ad-hoc
local signature, the Swift clients were relinked, and both runtime profiles then
passed their loaded-image identity check. The original library copies and failed
logs remain preserved. This is component/source qualification, not a completed
installed archive producer or notarized release.

The C-specific short-buffer probe belongs to the separately qualified C path;
it is not claimed as a Swift CLI operation. The protocol engine remains shared.
The produced client-side advertisement is verified but does not yet replace the
successor fixture's server prekeys. Kotlin publication, complete installed-package
qualification, independent implementations, physical/minimum systems and security/
post-compromise recovery review remain open.
