# Installed browser peer roster admission and revocation

The browser device now exposes `admit_peer_roster` through the original owning operation. It verifies the independently pinned signed roster and calls the shared active service's existing admission algorithm. The binding adds no protocol, storage format, private-key export or parallel authority logic. A known remote account is required; the local account still uses original enrollment R. An exact canonical retry checks live authority and reports the installed checkpoint, not which attempt first committed it.

Four fresh installed Chrome Worker cohorts cover normal admission, an unprocessed request loss, a processed head-advance reply loss and cancellation after the processed advance. Faults are armed after device activation and immediately before the target API. The before case drops the selected read/request before native dispatch; it is not labelled an unprocessed Commit. Unknown results close the owner, and original reopen plus the same signed target recovers the actual head.

Every cohort establishes an original session and exchanges real application data. After the new member-preserving peer roster is installed, the same historical bundle/session carries authenticated traffic in both directions. An empty next roster then revokes the peer. A session descriptor retained across that update cannot send (`Scope`), later reopen is refused, and neither rejection emits a peer request. The old target is rejected rather than rolling revocation back; exact canonical revocation retry remains available. The local journal and prekey remain unchanged, and application effects are not duplicated.

Each cohort also rejects rollback, same-version fork, unknown account, local-account substitution, wrong family, corrupted signature, closed policy and closed runtime. Five invalid timestamp aliases are rejected without coercion hooks or closing a still-valid owner. Eight native peer-roster regression cases, ten installed base browser modes, 53 package/inventory controls, strict native/WASM Clippy, WASM Rust 1.90, formatting and installed Node/TypeScript consumers passed.

The archive binds the exact source overlay, package and native binaries to complete operation results and peer traffic. Repetitive raw witness/native traces remain in the original task-local runs with a complete hash manifest; witness metadata and raw messages adjacent to the selected loss cuts are included. No private signing/wrapping material, journal databases or browser profiles are included. This exercises manual receipt/admission of independently trusted rosters, not an automatic distribution service. Credential, policy, account-root transition, migration, deployed-network, independent-implementation, performance, PCS and full-release obligations remain separate. Reopening an owner for every action is deliberate persistence testing, not steady-state performance measurement.
