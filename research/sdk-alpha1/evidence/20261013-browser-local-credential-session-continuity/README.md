# Browser session continuity across local credential renewal

Nine fresh installed Chrome Worker/native cohorts qualify the existing product engine at `8b15054f9f014ccca9cc92f3507e5027b268860d`. This change adds evidence and an isolated driver; product code is unchanged. The same installed archive previously qualified for peer credential admission is used, with every consumed source, static consumer file and native fixture binary checked again against its recorded hash.

Each cohort establishes one original session, loses the browser message's consumption acknowledgement, leaves a reverse native message dispatched without acknowledgement, and loses the first PQ rekey reply. The browser then renews its own credential through the public original-operation request, independently issued grant, stage, prepare, signed required-witness commit and cleanup APIs. Activation is a separate operation. The native peer explicitly admits that grant through its active owner and reopens the original session. No replacement bootstrap hides continuity failures.

The cases cover normal renewal; loss after witness commit; loss of the cleanup acknowledgement; an attempted close after the witness has committed; cancellation during a held commit reply; actual expiry of the local credential; actual expiry and renewal of both endpoints' credentials; and two forced Worker terminations. In the expiry cases, wall-clock expiry occurs after the original pending traffic was established and before renewal starts. Original expired bundles remain invalid for a fresh bootstrap. The original journal and logical prekey inventory survive; fresh prekeys can be generated under the successor credential. Non-expiry cases retain the exact original prekey.

For both termination cuts, the server holds its reply for 20 seconds after processing the actual commit or acknowledgement. The parent observes the original exclusive browser storage lock, calls `Worker.terminate()` within one second of dispatch and before the 30-second SDK timeout, and observes that lock disappear. It sends no SDK close or cancellation request. Reopening recovers the exact original proposal: pending after the commit cut, committed after the acknowledgement cut. Reconciliation completes original cleanup. The captured command digest is independently reconstructed from the proposal and checked against the witness trace, so the cuts are bound to commit and acknowledgement rather than an arbitrary request number. This is Worker termination evidence, not whole-browser, OS-crash or power-loss evidence.

All nine cohorts retain epoch 0 with the original epoch 1 pending across renewal, replay the first lost control frame byte-for-byte and complete epoch 1. Pending application ciphertext is replayed byte-for-byte and gets its authenticated consumption result. The reverse message is consumed once; replay returns the same acknowledgement without invoking the application again. A new message succeeds. Each trace contains exactly one original bootstrap. Same-key credential renewal plus a completed rekey is not a PCS claim.

The first native fixture build failed with E0369 because one `identity()` result lacked error propagation. The fixture was corrected; the initial attempted run could not find that binary and produced no completed cohort. Both failure logs are retained. The corrected native build and the four producers containing nine cohorts exited successfully. All cohorts are closed and must not be reused. Existing strict compilation, MSRV, base browser and native regression results remain bound to the unchanged engine revision in the preceding peer-credential evidence; they were not redundantly rerun for this evidence-only change.

An ancillary CI diagnosis preserves the failure of Android job `115377130350` in run `38419890920`, also at this engine revision. The full consumer completed qualification. The minimal consumer installed successfully and returned its matching run ID with `runtimeVersionOnly` passing, but subsequent cleanup could not establish current APK ownership: copies were 2,780,672 bytes and then zero bytes instead of the expected 13,702,871, followed by device-unavailable observations. Cleanup remained unresolved and the job correctly failed. These logs do not establish why the emulator transport deteriorated and do not show an SDK assertion failure. No rerun, relaxed ownership check or physical-device deficit is inferred from this event.

`CAPTURE.zip` includes public operation results, peer frames, selected fault witness frames, driver and fixture source, package receipts, and Android failure diagnostics. Its manifest hashes every member; a separate manifest covers complete repetitive native/witness traces retained in closed task-local directories. Private roots, wrapping keys, journal databases and browser profiles are excluded.

The endpoints share the Rust implementation and loopback network. Independent implementation, cross-host/device qualification, performance, full lifecycle coverage, PCS analysis and release readiness remain separate work. This evidence closes original-session continuity across local and bilateral credential renewal; it does not close the 0.2.0 release goal.
