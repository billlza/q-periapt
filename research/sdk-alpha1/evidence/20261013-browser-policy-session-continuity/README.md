# Installed browser session continuity through independent policy renewal

The existing browser reopen API binds an original session to its original live policy. Its refusal of P1 is a correct boundary, but the browser lacked access to native continuation admission. A real installed-package counterexample first established a session, retained an unacknowledged message and pending epoch-1 PQ control, completed independent P and activated the same journal; the legacy reopen then returned Conflict. The original pending work was still present. This counterexample is retained as red01, not counted as a successful continuation.

QPeriaptContinuitySessionReopenRequest now authenticates the original public bundle against an independently pinned historical P0, exact peer identities, directory, role and original session ID. It holds immutable authenticated metadata, with no runtime, signer, journal or operational permission. The existing native request gains Clone so the browser can reuse that metadata without consuming or manufacturing an owner. BrowserDevice.reopen_continued_session delegates to the active original service's existing reopen_continued_peer. The journal must admit the actual completed current authorization, identity, roster, archive and required witness before returning a session descriptor. The legacy API is unchanged and still refuses P1 in every successful cohort.

The product change adds a 59-line WASM binding module and a small browser delegation, reusing all native authentication and continuation logic. It adds no new policy state machine, fallback, current-authority cache or implicit transport retry. The exact Rust source inventory increases from 629 to 630 and the browser export equality check includes the new approved request type.

Eight fresh installed Chrome Worker/native cohorts passed: unilateral P, bilateral P, actual bilateral P0 expiry, lost processed Commit reply, lost ACK reply, cancellation, and actual Worker.terminate after processed Commit and ACK. Each starts with an original established session, retained application ciphertext in both directions and a pending PQ control. After P it retains the original journal/session/message identity and pending epoch, replays the first control and original ciphertext byte-for-byte, completes epoch 1, authenticates both directions' consumption, avoids a second host effect on duplicate delivery and sends a fresh message. The two Worker terminations happen while a real processed reply is held, before worker cleanup. The ACK cut observes Applied locally with retirement still unfinished, then reconciles the original transaction.

The bilateral fixture issues a separate native account approval and policy approval against its independently retained registration and actual journal. It does not reuse the browser account's approval. The expiry case signs P0 with a 240-second lifetime, prepares the original sessions and pending work before expiry, waits for actual wall-clock expiry, then issues/adopts P1 and restores both original sessions. Credentials/rosters remain live. No old current-time argument or manufactured live P0 runtime is used for recovery. Immutable native fixture binaries and installed static web bytes are hash-bound; endpoints share the Rust implementation and loopback, not an independent protocol implementation or cross-host release.

Current-source validation also passed 11 native bundle/history regressions, native all-target and Continuity-enabled WASM Clippy with warnings denied, Rust 1.90 WASM checking, 53 package/inventory controls, installed Node and strict TypeScript consumption, ten browser base modes and formatting. The prior full-suite and 73-test policy receipts belong to earlier source revisions and are not relabelled as runs for this change.

Two additional failed cohorts remain in the archive. The first native policy fixture created trace children with mode 0755 under a 0700 parent; the existing private publisher refused before the first trace write. A separately built v2 fixture creates its new children with mode 0700. The original source, executable and failed cohort remain unchanged; SDK publication admission was not relaxed. A later cohort hit the caller's 10-second initial-handshake deadline during concurrent builds and browser cohorts, before policy renewal. Both native handshake requests returned successfully; their trace file spans were about 2.76 and 2.08 seconds. These spans do not account for the full client path or prove a root cause. After all other producers ended, fresh serial cohorts passed with identical source and deadline bounds. Contention remains a hypothesis, and these results make no performance or deadline-SLA claim. The failure is not discarded or turned into a product pass.

CHECKS.json binds source, installed package and CAPTURE.zip. The archive includes driver/helper sources, counterexample and failed logs, current results, public peer transcripts, selected signed witness faults, package receipts and a hash manifest of remaining closed raw traces. It excludes private roots, wrapping keys, databases, profiles and executables. All successful cohorts are closed before sealing.

This is original-session continuity and observed PQ protocol progress, not a post-compromise secrecy proof. Full browser G/P/T/roster composition, every lifecycle interleaving, whole-browser/OS crash, deployed migration, independent implementation/cross-host, new physical-device qualification, controlled performance, PCS analysis and full 0.2.0 release remain open. Accepted physical-device cohorts remain closed and unchanged.
