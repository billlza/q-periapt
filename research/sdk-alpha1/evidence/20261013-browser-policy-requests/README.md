# Original browser policy-renewal issuer requests

The browser owner and installed WASM package now expose local and required-witness policy-only issuer requests through `QPeriaptContinuityPolicyRequest`. They delegate to the same original enrollment/journal admission as native callers. Returned public metadata includes the original operation, immutable journal/owner, exact original and current credentials/rosters, original/previous policy checkpoints and prior policy authorization. No signer, raw storage handle, live runtime owner, durable reservation or issuer approval is exported. An admitted failure closes the owner and recovery reopens the original registration.

Seven fresh installed Chrome Worker cohorts cover local and required protection, wrong witness, refusal of local fallback, lost read reply, cancellation of a held read reply and real expiry of the original signed policy. All request retries retain the original operation and exact public materials without changing journal/prekey identity. A separate native issuer holds independently provisioned account and policy keys, original registration and policy pins. It checks the request against those inputs, signs both approvals for an actual successor policy and verifies the result at current time. Substituting the operation or reusing the account approval in place of the independent policy approval is refused. These are real cryptographic approvals, not policy adoption or current device activation.

The expiry cohort signs a fresh policy with a short actual validity before enrollment, keeps credentials current, activates before expiry and waits for wall-clock expiry. A subsequent current-policy constructor returns `Validity` before opening any device owner. The historical policy request still succeeds without creating a runtime, and independently approved P1 verifies at the current time. No old current-time value or modified signed policy is used.

Two additional fresh cohorts first perform real same-key credential renewal G, including required witness preparation/commit/terminal-before-ACK cleanup and separate activation. Local protection returns the actual successor credential/roster in its policy request. The required-witness route instead returns `Conflict` before dispatch; the original G remains activatable with its original journal/prekey. This is an explicit unresolved native composition limit. `WitnessPolicy` validation, policy preparation and scope admission all reject retained G, while witnessed request construction presently uses the original credential as its current credential. Removing a single guard would not implement correct P-after-G authorization. Browser policy grant adoption/activation and complete G/P composition remain required work.

WASM Clippy with warnings denied, Rust 1.90 WASM checking, seven native policy-request tests, 67 native independent-policy regressions, ten installed base browser modes, 53 package/inventory controls and formatting passed. The exact Rust source inventory increased from 623 to 625 for two small modules (47 and 111 lines); the gate and guide agree. No product state machine, signature purpose, storage format, authorization check or cryptographic data path changed.

Development failures are preserved. The first native helper build started before its manifest existed. The initial helper incorrectly assumed diagnostic-only witness probe methods were product APIs; the final preparer uses public APIs and the unchanged isolated witness observer remains a separately hash-bound binary. Unused helper functions were removed, and approval output was corrected to serialize its public bytes. The first inventory control caught the stale guide count, which was updated without weakening the check. The first expiry fixture requested a prekey beyond policy validity and was correctly refused. The second wrongly expected owner closure when the expired policy constructor had failed before owner creation. New cohorts corrected those fixture assumptions; failed cohorts were not reopened or relabelled successful.

The archive retains public inputs/results, final helper sources, failed development logs, selected signed witness fault traces and package/source receipts. Complete repetitive witness traces remain in closed local cohorts with a hash manifest. Private roots, wrapping keys, databases and browser profiles are excluded. All nine successful cohorts are closed. The endpoints share the Rust implementation and loopback; this is not independent implementation, cross-host/device, performance, PCS or full 0.2.0 release qualification.
