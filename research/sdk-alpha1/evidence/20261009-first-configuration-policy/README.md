This component experiment composes first-use configuration, an original TLS session, independent protocol-policy renewal, and recovery of a message whose acknowledgement was lost before that renewal. It uses the existing public C, Swift and Kotlin owners; the native library sources and export surface are unchanged. The patch is reviewable and applies to `8218da58560b4485d162ebcd6c836ec7757c015f`, but it has not yet been integrated into the mandatory package qualification path.

All 48 fresh flows passed: C and Swift Debug/Release, plus Kotlin Debug/Release with G1 and Serial GC, each over local, signed TCP and mutual-TLS witness protection with fixed or recoverable SDK trust. The host supplies signed policy, independent trust and TLS inputs. Each device creates its own signing identity, wrapping key, enrollment, installation and journal; an existing private installation is not copied into it.

The receiver commits one application effect and exits with status 77 before acknowledging it. The sender then exports and replays the original policy-renewal request, rejects a modified approval signature without changing that request, stages the valid account-root and policy-root approvals, and completes the original local or independently approved witness transaction. A reopened owner selects the current target, reopens the original session through explicit peer configuration, and retries the original message. The acknowledgement, registration request, session/message identities and single recorded application effect remain linked. Mutual-TLS cases also assert that this measured path does not use the signed-TCP witness endpoint.
