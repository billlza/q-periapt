# Installed browser independent policy adoption and recovery

The browser owner and installed WASM package now continue an independently approved policy request through staging, local or required-witness commit, original-operation recovery and separate activation. QPeriaptContinuityPolicyGrant checks distinct account and policy approvals against the original request and independently authenticated original, predecessor and live target policies. Staging rechecks the retained operation and current authority. Policy proposal, historical status, witness observation and locally retained terminal/cleanup have separate types. None of them alone grants current traffic permission.

The implementation delegates to the shared enrollment state machine. It adds three focused modules (browser driver, WASM binding and public metadata types), each under 260 lines, plus two historical metadata readers on the active enrollment owner. It does not duplicate the policy state machine or add implicit network retries. No performance improvement is claimed from file length or module organization.

Real browser testing exposed a storage integration defect that compilation did not catch: witnessed P preparation, recovery and retirement still opened a native file database directly. Both initial required-witness cohorts failed with Database(File), while local policy adoption passed. Enrollment now obtains the database from its existing platform Storage abstraction, calls the same database-based policy logic and drops the database before persisting the next enrollment phase. This follows the existing roster-maintenance path, preserving the original lease, terminal-before-ACK ordering and authentication checks. The public native path entry points retain their behavior; the unused private path-based retirement wrapper is removed.
