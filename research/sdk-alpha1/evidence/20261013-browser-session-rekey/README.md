# Installed browser session rekey

This candidate extends the owned `QPCXCH01` exchange with bounded delivery of the existing signed request, offer, response, final and receipt. It reuses the journal's control-delivery preparation/replay functions, now available in both native and browser builds. No cryptographic grammar, journal schema, key derivation, or signing owner was replaced.

`drive_session_rekey` retains one explicit target, checks an absolute deadline and allows 1–128 requests without automatic network retries. An error or exhausted request allowance closes the owner while preserving original pending work. A locally completed non-proposer redispatches its retained receipt after a lost result. `session_rekey_progress` exposes local confirmed/sending/receiving/pending epochs; the completion result reports local epoch and request count only. A carrier's empty marker cannot establish completion of unfinished work. Local completion is not remote receipt, fresh peer availability, or evidence of post-compromise secrecy recovery.

The actual installed npm web entry was exercised in Chrome dedicated Workers using OPFS/IndexedDB and a required signed native witness. Browser-initiated targets 1 and 2 exercise both proposer roles. A native non-proposer then initiates target 3 through the same high-level API, deliberately losing each dispatch result and reopening the original owner; every continuation checks exact original wire bytes. Real application messages in both directions use epoch 3 and end with authenticated consumption. Seven cohorts cover the normal path, lost first/final responses, forged empty response, corrupted signed response, a previous target's valid receipt, and exhausted exchange allowance. These are finite same-host schedules through the shared Rust implementation and explicit loopback HTTP.

Native tests cover ten before/after transport-loss cuts, false completion, retained targets, owner closure, repeated roles and real epoch-three application traffic. The existing native TLS control suite also passes, including real process cuts before each reply, cancellation, deadlines and stale-target rejection. The installed base browser suite, TypeScript consumer, strict native/WASM Clippy, minimum Rust 1.90 WASM build and source inventory/package controls are recorded separately. Earlier compile diagnostics are retained; no warnings or assertions were disabled.

`CHECKS.json` identifies the exact tested source overlay and installed package. `CAPTURE.zip` contains drivers, fixture source/lockfile, test results and command logs, the happy-path public protocol transcript, and source files. Its `MANIFEST.json` identifies every member by length and digest. Complete fault traces remain at the original local run paths. Private authority keys, wrapping material, journals and browser profiles are excluded. The existing witness fixture is preserved in `../20261013-browser-required-witness`.

The core control adapter and the browser and WASM wrappers occupy separate focused modules. This is integration and recovery evidence, not a performance improvement claim. Deployed HTTPS/CORS and browser/version coverage, independent/cross-host implementation, full root/roster lifecycle, migration, performance and recovery-security requirements remain open for 0.2.0. No public package publication or release approval occurred.
