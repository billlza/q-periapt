# Installed browser owned session exchange

This cohort uses the actual locally packed and installed npm web entry, Chrome dedicated Workers, OPFS/IndexedDB persistent owners, an independent native endpoint, and a required signed witness. Both endpoints use the shared Rust protocol implementation. Traffic uses explicit loopback HTTP diagnostic endpoints. It is not HTTPS/CORS deployment, cross-host, independent-implementation, or complete browser-matrix qualification.

The public API now admits independently pinned peer bundles, establishes or reopens exact sessions, retains original message IDs and input, reports outgoing state, sends messages, and serves authenticated delivery to a host consumer. A local reopened descriptor is not a fresh peer-liveness receipt. An authenticated old consumption prefix is `PrefixPending`, never successful consumption.

The successful suite covers a normal bidirectional connection plus 16 failure scenarios: lost final handshake response, corrupted READY, lost data ACK, replayed old ACK prefix, native effect committed before failure, native effect rejected, closed policy/runtime, wrong directory pin, invalid bundle, browser effect committed before failure, hostile thrown cause, misleading error code, application deadline, peer deadline, and peer cancellation. Recovery preserves original wire bytes and authenticates consumption at the sender. Browser effects and deduplication commit together in a strict IndexedDB transaction; an already consumed duplicate does not reinvoke the callback. Cancellation/deadline cannot undo or stop an external host callback, and the SDK makes no global exactly-once promise.

The shared bounded Fetch implementation also passes the nine original required-witness lifecycle cases using a byte-identical copy of the installed package in a separate serving root and browser profile. The base installed browser suite, installed host-helper checks, TypeScript consumer, Rust 1.90 WASM check, strict WASM Clippy and relevant artifact controls are recorded separately.

`CHECKS.json` binds the tested source overlay on `cd9e77bb`, package digest, validation scope and capture members. `CAPTURE.zip` contains drivers, native fixture source/lockfile, results, command logs, the successful happy-path public transcript, and tested source files. Full fault transcripts remain at the recorded local run paths. Private keys, journals, wrapping material and browser profiles are excluded. The existing witness fixture source and diagnostic accessors are preserved in `../20261013-browser-required-witness`; that fixture is not a production API.

Two failed attempts are retained. The first used a fixture effect directory with mode 0755 and was correctly refused by private-file publication; fresh fixtures use 0700. The second omitted the dependency optimization profile used by existing native Debug consumers and exceeded the unchanged ten-second client deadline. The fixture now keeps its driver in Debug and optimizes dependencies with debug assertions and overflow checks still enabled. This setup change and process timings are not SDK performance results.

The implementation shares one bounded carrier between witness and session traffic. Public trust, connection wrappers, browser orchestration, and host-consumer handling are separated into focused modules. Browser rekey, root/roster transitions, migration, deployment qualification, independent interoperability, performance and recovery-security work remain separate release requirements. No package was published and this receipt does not approve a release.
