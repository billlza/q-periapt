# Browser peer credential admission and original session continuity

`admit_peer_credential_renewal` now connects the browser active owner and typed independently verified grant to the existing owning-service transition. It preserves original operation, P0, current policy/runtime, known peer history, account authority and local-membership checks. A signed same-account update can be committed before refusing a revoked local member; a failed call must not be described as non-commit. It does not renew the local device or create a peer session.

Five fresh installed Chrome Worker/native cohorts cover normal admission, an unprocessed first witness request, a reply lost after the actual head advance, cancellation of a held post-advance reply, and actual peer credential/manifest expiry. Before renewal, each establishes one session, loses the browser message's consumption ACK, leaves a native reverse message dispatched without ACK, and loses the first PQ rekey reply. The native peer independently issues a real G with its retained root, stages/prepares/commits it through the original enrollment and required witness, and separately activates the same journal with its successor credential. The browser then explicitly admits the original peer G.

Across admission and exact retry, the original session and local journal/prekey remain unchanged. Pending rekey progress remains epoch0 with original epoch1 pending. The first control frame is replayed byte-for-byte and reaches epoch1. The pending browser ciphertext is replayed byte-for-byte and gets its original authenticated consumption result. The reverse message is consumed once; a duplicate returns the same ACK without invoking the application. A new post-G message also succeeds. Exactly one initial bootstrap remains in each trace; none is synthesized to hide renewal continuity failures.

The expiry cohort waits for real wall-clock expiry before native renewal. Reopening the original browser session first fails Validity. After actual native renewal and browser G admission, that same original bundle/session recovers all pending work. The expired original bundle is still refused for a new bootstrap before peer dispatch. No historical current-time value is fabricated. Wrong operation, closed policy and closed runtime are refused in all cohorts; caller-visible owner closure is checked.

The first fixture failed before writing its first renewal witness trace: the helper used the default0755 mode for a new diagnostic child directory. The private publisher correctly rejected it. The helper now creates new0700 directories; the failed cohort and source are retained, and no existing directory's permissions or SDK admission checks were weakened. Established native message frames now use `serve_session_message` on the original reopened session, rather than treating each message as a fresh peer admission; bootstrap frames retain their normal live checks.

Six relevant native regressions, including exact sync-cut recovery, local-identity/policy isolation and durable observation of same-account local revocation, passed. Ten installed base browser modes,53 package/inventory controls, strict native/WASM Clippy, WASM Rust1.90 and formatting passed. Public operation results, peer frames and selected actual witness-loss traces are archived. Complete repetitive raw native/witness traces remain in closed task-local cohorts with a full hash manifest. Private roots, wrapping keys, journal databases and browser profiles are excluded.

The ancillary CodeQL audit matches the fetched v2.27.1 SummaryStats entry query to the frozen linked-query SHA-256. Its imported TaintReach source counts reach from active modeled sources to all dataflow-node sinks, excluding summary nodes from the final count. This is consistent with the stalled evaluator trace. The endpoints share the Rust engine and loopback. This qualifies peer-G admission and original-session continuity, not independent protocol implementation, simultaneous renewal of both peers, actual browser process-kill recovery, performance, device coverage, PCS or release readiness.
