# Physical iOS managed registration and witnessed message recovery

A signed Release Swift application on the offered USB-connected iPhone 16 Pro (iOS 27.0) completed four cases: fixed/recoverable SDK trust and signed TCP/mutual-TLS witness runtime. Initial genesis preparation uses the explicitly selected signed-TCP witness pin. After selecting mTLS, the native witness fixture asserts no further signed-TCP exchanges. Both the enrollment identity and account-authority wrapping key/database are created on the phone. The host transfers public trust/approvals and test TLS material; it never copies a device signer, wrapping key or journal onto or off the phone.

The host verifies the first device request before issuing the credential and requesting account association. The iPhone provisions its own registry, associates the device and peer, and reopens the same mapping. Missing witness (216), wrong witness (103), preparation cancellation (302), bad signed receipt (218), omitted registry (211), and closed/finally released registry (202) are refused. Untrusted witness-named files placed in the private installation do not replace the explicit caller pins.

All four cases establish actual TLS to the native C receiver. It commits one business effect and exits with 77 before acknowledgement; after closing and relaunching, the iPhone retries the original session/message and obtains its acknowledgement without another effect. There are 66 successful app launches, 12 peer TLS exchanges and 486 phone-to-witness exchanges. Twenty-eight refused reconnections after the intentional receiver exits are preserved as transport failures, not successful exchanges. The bounded USB relay transfers opaque bytes and supports up to 64 sequential streams per endpoint per invocation. Its original refusal-handling bug and a no-payload capture mismatch are retained with their logs.

Public records are checked against the existing registration/intent/genesis verifier, exact account mapping, original session/message/effect, and bounded witness transcript framing. Eight altered captures are rejected. Native execution verifies signatures; this reader is not a second crypto engine. All archive member hashes and extracted public records are reread. The app was uninstalled and absence observed.

This closes the physical managed first-registration/witness/unknown-message route. It does not qualify iOS expiry/renewal, device or root replacement, background/Data Protection transitions, package distribution, physical power loss or an independent protocol implementation. The shared Rust engine and current Main storage/Swift source are used. The agreed single-phone Android acceptance remains passed.
