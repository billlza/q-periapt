# Installed browser roster maintenance

The product web entry now coordinates the original enrollment's same-credential roster update. A required-witness target uses the existing R protocol, independent root-signed roster and witness preparation. The browser owner retains the exact proposal, persists the actual terminal before ACK, and keeps recovery separate from current traffic admission. Historical policy verification requires the independently retained root, family, checkpoint and signed statement; it constructs no live runtime and grants no new traffic authority.

The first real installed browser run failed with `Database(File)`: preparation and later recovery helpers still opened native paths. The corrected path opens the retained platform storage and reuses the original authenticated database algorithms. No witness, account-authority or durability check was removed. Local expiry recovery uses the same storage boundary. Raw failed and successful runs, source overlays and package identities are retained in `CAPTURE.zip` with a verified member manifest.

Fourteen fresh installed Chrome Worker cohorts cover Applied, Closed, lost Commit reply, lost ACK reply, Close after remote commit, timeout, cancellation, absent independent witness preparation, closed policy, substituted proposal, forbidden abandonment after reservation, local update, expired uncommitted local target and refusal of a required-witness local fallback. Each operation closes its owner and reopens the same registration. Recovery-only calls construct no live runtime. Retried preparation returns the same 417 bytes; terminal history survives ACK and subsequent activation. Existing journal identity and original public prekey remain unchanged. Missing witness history is not called uncommitted; Close after commit stays Applied.

The scalar regression reproduced `2^64 + 1n`, `1n - 2^64`, string and boolean values being accepted as version 1 by the old installed binding. Version, generation and time inputs now require exact unsigned-64 BigInt values. The final package rejects these aliases, and each browser cohort rejects ten malformed account/time inputs without executing coercion hooks or stranding the owner. TypeScript signatures remain bigint.

Validation includes 24 native roster tests (including synchronization and process-termination cuts), one original local-expiry regression, ten installed base browser modes, 53 package/inventory controls, strict native/WASM Clippy, native/WASM Rust 1.90 and formatting. Package production ran real installed Node consumers and TypeScript 7.0.2. An initial fixture accidentally narrowed the target roster start beyond the original prekey validity; the SDK correctly rejected that request. The corrected independent root fixture retains the original start and caps the end at the credential validity. The failed attempt is retained; no admission rule was relaxed.

This evidence uses actual browser IndexedDB, Web Locks and OPFS with a loopback signed witness sharing the Rust protocol implementation. It does not establish installed pairwise-session continuity across the update, independent implementation, deployed HTTPS, device coverage, performance, PCS or release readiness. Credential, policy and account-root transitions remain separate browser integration work. Private signing/wrapping material, journal databases and browser profiles are excluded.
