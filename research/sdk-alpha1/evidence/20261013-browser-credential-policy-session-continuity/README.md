# Installed browser credential then policy session continuity

This evidence qualifies the actual G→P composition on the unchanged product engine at 8b9e2406. It uses the previously built, installed and source-bound policy-session package. No SDK implementation, storage admission, cryptographic policy, format or timeout is changed in this step.

Each fresh cohort first establishes a real browser/native session and retains an unacknowledged application message, a reverse-direction message and a pending epoch-1 PQ control. The browser completes a plain same-key credential renewal G, and the native peer explicitly admits that exact root-approved successor. Independent P then uses the same original C0/journal/owner with the actual C1/R1 as current authority. After activation the original session and pending operations remain: control and ciphertext are replayed byte-for-byte, epoch 1 completes, both directions' consumption is authenticated, a duplicate invokes no second host effect and a fresh message succeeds. The historical G result remains intact after P.

The P issuer retains an independently issued G record separately from the browser request. It re-verifies that grant under the original account root, original policy binding and pinned successor roster, checks its original owner/C0 and exact C1/R1, then compares the request with those independently held materials. In every cohort a stale request substituting C0/R0 for current C1/R1 is refused before any P approval output is published. The usual operation-substitution and account-as-policy-approval negative controls remain. Trust is not relaxed to accept arbitrary caller-supplied successor fields.

Four serial cohorts passed: normal G→P; lost processed G Commit reply followed by lost P ACK reply; lost G ACK reply followed by actual Worker.terminate while the processed P ACK is held; and sequential real expiry. In the two fault cohorts G and P are independently faulted once under distinct fixture fault modes, then reconciled under their original IDs. They are not replaced by new operations. The Worker cut occurs before worker cleanup, with a durable local P Applied terminal but unfinished retirement.

The expiry cohort prepares original pending work while C0/P0 are live, waits for C0 to expire, completes G and native peer admission under still-live P0, then waits for P0 to expire. It issues/adopts P1 using C1 and separately renews the native peer's policy, preserving both original sessions. C1 and the native peer's credential remain current. No backdated current-time value, reconstructed identity or runtime for expired P0 is used to finish this chain.

Validity is the signed half-open interval [from, until), as defined in src/identity.rs. The recorded G renewal observation is exactly at C0's exclusive until second, which is expired. The first sealing checker incorrectly demanded a strictly later integer second. Its original checker and unchanged timestamps are retained; the final checker uses the existing protocol boundary and also requires independent issuer expiry observations. No product assertion or data was altered to turn a live credential into an expired one.
