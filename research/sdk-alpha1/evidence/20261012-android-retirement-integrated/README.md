# Integrated Android replacement and retirement

The normal installed-package qualifier passes Debug and Release with the required
25-test catalog. It executes **3,570 Java processes**: 1,784 lifecycle calls plus
one JNI boundary process per profile. The new Android-created replacement and
retirement lane contributes 128 calls and twelve actual process cuts; the existing
roster lanes contribute 1,960 calls across 44 exported routes.

The original and successor create their own keys and journals through Android
APIs. Explicit counterparty roster admission enables fresh successor traffic;
exact retry preserves one successor effect and the original device's effect.
Original report/acknowledgement and journal/signer erasure survive interruption,
while wrong-purpose and altered-report inputs remain rejected by the native SDK.

`CAPTURE.zip` contains 13,407 hashed source, command and public-data members.
Archive-only readback verifies every member hash and reexecutes all roster and
retirement public readers. Compiled source, package inputs and qualifier modules
were unchanged throughout the run. No private device keys or journals are archived.
The earlier accepted AAR's 60 library/JNI source inputs match this adapter; its
single-phone physical acceptance remains valid.

This seals the main-source retirement integration. The separately qualified
account-root adapter is the next integration step. CI and full 0.2.0 release
admission remain separate; this checkpoint does not make a release claim.
