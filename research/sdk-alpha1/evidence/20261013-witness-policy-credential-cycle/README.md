# Credential renewal after independently witnessed policy adoption

An original required-witness enrollment can now complete an independent policy update P, then a separately authorized credential renewal G, without replacing its journal or adopting a joint G/T authorization. Preparation requires the exact completed P and retired coordination. The original terminal is persisted before witness ACK; Applied remains Applied through lost replies, restart, closure requests and historical expiry.

The shared G transaction kernel remains in use. The witness extension has a small dedicated module; the enrollment decoder now names its format flags instead of passing seven positional booleans. These changes improve reviewability, not a measured performance result. New canonical tags distinguish retained independent P from joint T: QPCRNP03/QPCRNC03, QPWINT08/QPWINT09, QPANC019, QPRHST09 and QPENST18. Authenticated old-format relabelling is refused. These are unpublished candidate formats, with no deployed migration claim.

Native qualification ran the entire candidate library: 951 passed, none failed or ignored, in 1209.05 seconds. Its receipt binds the exact source set and test executable before and after execution. Tests include eight actual enrollment-process kill cuts, four witness-process kill cuts, successive P/G/P/G, original bilateral pending ciphertext and PQ control, target-free cancellation, wrong authority/format rejection and retirement reports at three cuts. Native all-target Clippy denied warnings; Rust 1.90 WASM checking passed; 21 retirement controls and 60 package/storage/CodeQL inventory controls passed.

The installed npm package was exercised in Chrome with original required-witness sessions and independently registered issuer expectations. Nine fresh cases cover ordinary P/G, lost Commit reply, failure before dispatch followed by Closed and a fresh G, lost ACK reply, two actual Worker terminations, target-free cancellation followed by fresh G, successive P/G/P/G, and real C0/P0 expiry before G. The current policy is authenticated from independently retained P history, never adopted from the incoming request. A stale P0 request is rejected before issuance. Each successful case retains its journal, operation identities, exact original ciphertext and first PQ control bytes; epoch 1 completes, messages are consumed in both directions, duplicates do not repeat the application effect, and fresh traffic succeeds. Ten existing installed-browser modes and installed Node/strict TypeScript checks also passed.

P1 is adopted by both browser and native peer. In the successive case only the browser adopts P2; the native peer remains on its still-live P1. This is not bilateral P2 qualification. Expiry uses real wall-clock time and the half-open validity interval; native unit tests separately use explicit logical clocks.

Development failures remain preserved. Two preliminary full-suite runs were deliberately stopped and reaped before any source edits: V1 had a mistakenly short supervisor; V2 reproduced an existing local T/P/G regression. The final run restored the established 2700-second bound. Separate red/green regressions cover that local path and Closed G followed by the next P. The first helper compilation used private historical getters and failed; the corrected helper uses public verification and explicit issuer registration. Its isolated witness lockfile repair reuses the exact previously qualified helper dependency lock, without changing the product lockfile.

CHECKS.json binds the tested overlay, complete native source manifest, installed package and CAPTURE.zip. The archive contains drivers, helper source, public inputs, terminal logs, selected signed fault transcripts and hashes for remaining raw traces. Private keys, wrapping keys, databases, browser profiles and executables are excluded. Qualification requires terminal processes and frozen source; closed cohorts are not reopened.

The binding audit records a concrete remaining gap: Swift's existing extended metadata reader accepts joint-T format 02 only, and Android's JNI credential route exposes the fixed-size plain-G format 01. The new independent-P format must be represented explicitly through those existing binding paths and qualified with installed consumers. This native/browser record does not qualify those bindings or update accepted physical-device cohorts. Independent implementation/cross-host testing, deployed migration, complete lifecycle admission, performance, PCS analysis and full 0.2.0 release remain open.
