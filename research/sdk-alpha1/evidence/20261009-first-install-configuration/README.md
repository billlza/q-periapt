# Explicit first-install configuration integration

The new `qpc_configuration_v1_*` route accepts independent original SDK trust,
signed initial policy/recovery proof, pinned protocol metadata, and local TLS
identity. Initial configuration, SDK store and wrapping key are published together;
unknown results have an exact reconciliation operation. Known committed state is
opened under original host trust, without trusting mutable root sidecars.
Registration takes the same native owner. Optional witness identity/endpoint/TLS
inputs are copied and retained explicitly. Target policy selection transfers the
actual SDK lease into original registration, without granting durable adoption.
Swift and Kotlin provide matching owner-based interfaces; Kotlin private input
snapshots have explicit close and scoped FFM cleanup. Product ABI 2 is unchanged;
the unpublished independent `qpc-owner/1` candidate has 130 exports.

Host-store additions preserve a live database lease across no-replace directory
publication, reject original recovery proof/root substitution against authenticated
committed state, and never repair missing keys/state automatically. Remote public
genesis import requires separately authenticated and approved control-plane input;
it is not a network authorization proof.

`CHECKS.json` distinguishes prior component captures from this integration. The
integrated native coordinator and new artifact reader ran the C, Swift and Kotlin
installed clients against both native profiles; Kotlin additionally ran G1 and
Serial GC. Every language has fixed/recoverable SDK trust crossed with signed TCP
and mutual TLS witness, original request replay, missing/wrong witness rejection,
cancellation and activation/reopen. Swift/Kotlin also exercise configured target
lease transfer, admitted failure, reconciliation and runtime disposal. Native short
headers are tested against a guard page. The component implementations match the
previously qualified snapshots; this is not a full rebuilt distribution result.

The small attached archive contains only selected public input/request/genesis
records and execution logs. The reader verifies complete scenario coverage,
canonical request scope, account-root digest binding, exact original request replay,
genesis linkage and a closed public-only file inventory. Signature verification is
performed by the shared native engine; the public reader is not an independent
cryptographic implementation. Collector/native source snapshots and large candidate
archives remain in the local captures referenced by `CHECKS.json`.

The CI collectors now require the five exports, all 39 C admission tests and all
62 Kotlin tests. New installed execution is wired into C, Swift, and both Kotlin
collector lanes, and public configuration evidence is retained by CI. Existing
lifecycle tests remain required. Strict Clippy, normalized-source format, and the
35 focused artifact reader tests passed at this checkpoint. Full current-source
preflight, rebuilt package qualification, new-code CI, native Linux/physical devices
and broader protocol/release gates remain open.
