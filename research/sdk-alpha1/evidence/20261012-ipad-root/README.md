# Physical iPad account-root lifecycle

The offered iPad Pro 11-inch (M4), running iPadOS 27.0.1, completes all five root routes under fixed/recoverable SDK trust: original target, transition to another independently approved target, transition after binding, adoption of an already committed winner, and signed noncommit/cancellation. The warning-clean Release application uses the same 24 public Swift library files and the same native archive as the integrated iPhone build. All 28 original/target signing identities and their private stores are generated on the iPad.

The final cohort completes 362 app calls, 62 actual app exits with code 77, and 20 separate native C receiver exit cuts. Exact proposals, retirement reports and logical erasure state survive reopening. Unknown successor activation returns 218; modified report bodies return 208 and wrong-purpose erasure returns 102. Closing the root controller revokes its still-reachable successor with 202. Signed noncommit stays Closed across restart and cannot re-enable the old freeze. Cancelling an idle controller prevents controller work while its already active successor remains valid until controller close.

Every route establishes fresh successor traffic with the original C counterparty, whose independently approved new root admission is explicit. Original-session/message identities and their recorded business effects remain unchanged across unknown delivery and retry. Each case has two distinct effects, one original and one successor; this is not a guarantee of arbitrary external exactly-once effects. The run records 50 peer TLS exchanges, 3,340 opaque witness streams and 140 actual refused reconnects after expected receiver exits. Ten altered public/execution captures are rejected. All 16,334 archive-member hashes and all ten route/profile exports are reread from extraction.

The final test application uses UIKit Scene lifecycle and executes the SDK only after the host returns an exact run-bound startup acknowledgement. All 362 startup admissions are separately checked. Earlier failures remain under execution/failures: a test owner was closed twice, a prior application exit had no SDK diagnostics, CoreDevice later returned 10004 before SDK dispatch, and a legacy UIKit entry trapped in the platform's no-Scene lifecycle check. The double close was corrected by a single owning lease; the final application adopts Scene lifecycle and a bounded startup handshake. The cause of the earlier opaque exit is not retrospectively asserted. No failed attempt is counted in the successful cohort.

The run-owned app was removed. No private iPad keys or journals were exported. These are shared-engine platform and authorization results; they are not independent protocol implementation, physical power-loss, physical key erasure or post-compromise confidentiality-recovery claims. Installed binary-package execution and background/Data Protection remain separate work. The accepted single-phone Android gate stays passed.
