# Physical iOS credential expiry and unknown-commit recovery

Four fresh iPhone installations use fixed/recoverable SDK trust and signed TCP/mutual-TLS witness runtime. Their protocol signing identities and account-authority wrapping keys/databases are generated on the offered iPhone 16 Pro (iOS 27.0); only independent provisioning/approval material and test TLS material come from the host. All 130 app launches pass in a warning-clean Release application.

Each case creates a real TLS session and one message whose native C receiver persists its business effect before exiting with 77. Before the original credential expires, the independent account authority prepares a renewal for the existing signing key. The test waits for actual clock expiry, then observes 104 for old activation and for a fresh registration request. A modified renewal grant is refused, exact repeated staging/preparation retains the same operation, and closed/absent account authority refuses a new commit.

The witness durably commits the original renewal and truncates its reply: signed TCP sends only a prefix; the mTLS fixture truncates an encrypted reply. The iPhone reports unknown result 218 and closes the affected owner. Reopening without an account registry can reconcile and replay that already-committed historical operation, with no new commit dispatch. Fresh activation still requires the live original registry and returns 211 without it. After valid activation, signer/journal identity remain unchanged. The receiver explicitly admits the renewed credential, and retry acknowledges the original session/message with one unchanged effect. This renews an existing credential; it is not signing-key replacement or post-compromise recovery.

There are 12 peer TLS exchanges, 542 phone-witness streams, four receiver exit cuts, and 28 explicitly recorded refused reconnections after those exits. Native checks enforce one renewal commit and zero historical redispatches per case, and mTLS does not fall back to signed TCP. Twelve mutations of expiry, operation/target, commit receipt, registry identity, manifest and execution identity are rejected by the public reader. It reuses the existing registration and credential record validators against the actual iOS log; no log names or test counts are rewritten. Signatures are native execution evidence, not a second crypto implementation.

The run-owned app was uninstalled. No private device keys or journals were exported. Policy expiry/renewal, device/root replacement, background/Data Protection behavior and installed-package admission remain separate iOS work; physical power loss and independent implementation are not claimed. The accepted single-phone Android gate remains passed.
