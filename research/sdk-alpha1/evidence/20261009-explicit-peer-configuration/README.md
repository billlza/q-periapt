# Explicit peer configuration through the original device owner

The C candidate now accepts copied peer trust/bundle inputs without a peer sidecar
directory. Swift/Kotlin expose immutable typed expectations and configured fresh
or original-session preparation through the same NativeOwner/parent lifetimes.
The native verifier, policy/roster rules, TLS engine and continued-policy
restrictions are reused. Product ABI 2 and existing path-based calls are preserved.

The prototype passed 42 native Release tests (plus Debug full/focused evidence),
strict all-target Clippy, Rust 1.90 all-target checks, and real C guard-page calls.
Swift passes 62 Debug/Release tests; Kotlin passes 64 Debug/G1 and Release/Serial
tests. Six outside-checkout Swift/Maven component archive flows passed real
registered-device TLS, receiver exit after application commit, roster refresh,
original-session reopen and identical-message recovery with one application
effect. Input-copy and Java public/synthetic boundaries were separately checked.

Lifetime probes preserve the actual language contract. Swift ARC can immediately
release the last hidden parent. Kotlin Cleaner is asynchronous; its probe observes
bounded return of all 64 slots before attempting storage reopen once. Both require
explicit parent close to invalidate retained children and permit original storage
reopen. Child cancellation must preserve a separately live parent. The first JVM
probe incorrectly required synchronous Cleaner disposal and performed a duplicate
close; only the probe changed. The library disposal implementation is unchanged.

The integrated installed gate passed nine actual process commands in each Debug
and Release profile: C short-header guard, configured C registration, configured
C device peers, Swift registration/lifetime, and Kotlin registration/lifetime with
G1 and Serial. Public readback and binary hashes were checked. These runs use the
qualified same-implementation component binaries and current integrated reader;
they do not claim a freshly rebuilt complete distribution. The initial gate used
a generic exporter with the wrong report schema; it was corrected to reuse the
existing registration exporter with an explicit configured-test selection.

New native/language tests and candidate exports are mandatory closed inventories.
The Rust tracked-source count is 441, with both added paths individually checked
for deletion/substitution. Existing legacy and witnessed cohorts remain required.
The new gate's public-only closure is retained by Linux and macOS CI artifacts.

`CHECKS.json` records identities and actual commands; `PUBLIC_CAPTURE.zip` contains
selected public records/logs only. Full local prototype captures are referenced by
hash, not treated as whole-release approval. First-configuration composition,
required witnesses/continued-policy coverage on the explicit route, the complete
installed lifecycle pipeline, new-code CI and the larger 0.2.0 gates remain open.
