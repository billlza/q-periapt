# iOS first-use identity and storage boundary

A signed Release application executed on the offered USB-connected iPhone 16 Pro running iOS 27.0. Fourteen launches cover fixed/recoverable trust, first-use cancellation, Swift ARC capacity, on-device identity creation, exact reconciliation, enrollment activation, and reopening the original identity after separate process launches. The host verifies both fresh registration-request signatures before issuing grants. Eight negative checks refuse symlinked or 0755 directories with code 203; subsequent ordinary reopening preserves each original identity. The run-owned test app was uninstalled and absence observed.

The baseline failed before identity creation because iOS was excluded from the host-store publication adapters. Enabling those paths exposed an app-path alias, then read access denied on sandbox ancestors. The candidate uses the same descriptor ACL, owner/mode, no-follow and no-replace checks as the macOS implementation, and the iOS O_SEARCH flag for intermediate directories. Final directory admission and sync remain unchanged. The app passes its own sandbox directory from raw realpath, avoiding Foundation path abbreviation. Native diagnostics were removed before this final run. All failures and the intermediate successful run are retained.

The exact candidate patch is retained in `IOS_STORAGE_CANDIDATE.zip` with its hash; complete isolated source inputs are in `CAPTURE.zip`. It is not yet integrated into Main. This run covers initial identity and process reopening; iOS network sessions, witnessed persistence, expiry, renewal, replacement, root recovery, and package qualification remain separate work. No physical power-loss or independent protocol implementation claim is made. No private device keys or journals were exported. The already accepted single-phone Android gate remains passed.
