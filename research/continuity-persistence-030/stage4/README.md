# Stage 4 responder prototype

The responder can lose its process after the real hybrid signature is readable and still recover the identical 4,714-byte response from its phase-5 record. In the process test the initiator accepted that signature **before** the responder wrote Ready. Exact recovery and the time of peer acceptance are distinct observations. The evidence supports recoverability at phase 5 under the tested authority and storage conditions. A property requiring every peer acceptance to follow phase 6 has a counterexample in this run. ## Scope and signing boundary

The Rust CodeQL profiles load the tracked overlay through the pinned prototype Cargo package. On native Linux and macOS they check all six module paths and digests against rustc depfiles. The separate recovery workflow executes the reference, Debug and Release experiments with Rust 1.98.1 and publishes the independently readable observations.

The native experiment is an opt-in overlay on `f70fa0970d7cbe27718309b8da11e7db4288c0e7`. The distributed 0.2.0 Cargo archive has SHA-256 `fd51d1ef614b6143867e381cc7b7099081fd259d7ee5145083db0a4d9d9bc6c9`. Eight reference paths, including the signer, Witness, journal, response and disclosure fixture, were compared byte for byte with that archive. The study keeps the original 0.2.0 entry point for the positive control and for legacy reservations. The candidate path binds its input explicitly. | Stage | Durable record and decision |
| --- | --- |
| Bind the responder input | The journal verifies the offer, role, epoch, predecessor, policy and current authority. Experimental private tag 10 contains the exact signed offer and zero encapsulation-token bytes. Existing private tag 4 still decodes the original 245-byte token. |
| Select the response | A dedicated KEM program receives the peer public key, context, signed SDK policy and the independently supplied policy checkpoint. It uses the real ContextBound SDK and OS randomness. Its only output is the ciphertext and 32-byte shared result over a bounded private pipe. The trusted journal computes the body and pending root, creates the existing 64-byte signing reservation and commits all three with the original write-intent and Witness protocol. |
| Sign and publish | The signing endpoint reloads the original journal and checks current authority. The proposed body supplied by the caller is an equality check. Only the retained body, original slot/purpose and retained signature coins reach the real ML-DSA-65/P-256 signer. The existing phase-6 transaction persists the complete wire before the API returns it. Replays after completion use the original retained response. |

The KEM executable receives no journal path, wrapping key or signing owner. Its environment is cleared and its working directory is empty. Local selection opens the installation without a device signer. Required-Witness selection keeps the existing device-authenticated Witness client inside the trusted journal process. The signing endpoint independently opens the journal and the real device key. The trust boundary excludes hostile access to that owner, its key file and the operating system. Same-user process isolation is sufficient here to distinguish a read of the speculative KEM process from a read of the signing process. It supplies no hardware protection or whole-host compromise guarantee. ## Observed crash and authorization boundaries

| Cut or request | Observation in both Debug and Release |
| --- | --- |
| Input intent durable, before image apply or KEM computation | Killed the responsible child with SIGKILL. The authenticated current row was phase 0. The pending row contained the original offer and either the 245-byte control reservation or the input-only candidate. The wrong wrapping key was rejected. Reopening applied the original pending target. |
| First proposal computed, before phase-5 persistence | Killed the selector with proposal A recorded as public bytes. The journal reopened in the input-only state. Asking the real signing endpoint for A was refused. A second genuine KEM attempt produced a different body B for the same operation. |
| B selected, requests for A or for B with expired authority | A was refused with `Conflict`. The expired request for B was refused with `Validity`. The common signing-provider observer recorded zero response-purpose calls on these requests and on selection. |
| Signature for B readable, before the Ready write | Killed and reaped the signing process at the exact post-signature hook. The initiator validated the captured bytes and produced its final flight. The responder reopened in `SignatureReserved`. Its next real signing call used B again and produced the same complete wire. |
| Witness committed phase 5, TCP reply lost | The real independent Witness store completed and its signed `Advanced` reply was verified by the observer before the connection closed. The caller received a transport error. Reopening reconciled the same command and head as `AlreadyAppliedExact` with a fresh attempt. The reopened selection returned B with a failing callback installed to detect any KEM rerun. |
| Witness committed phase 6, TCP reply lost | An independent loss at Ready again returned a transport error. Recovery reconciled the original phase-6 command on its original fence. Its revision was exactly one above the phase-5 revision. The cached complete response matched the bytes read before the signing-process crash. |
| Post-recovery traffic | Both peers confirmed epoch 1, closed and reopened. The original response still replayed after epoch confirmation. Three fresh messages in each direction were delivered, consumed and acknowledged on the installed-process paths. |

The provider audit is at the common signing backend entry. It records the public response body for the response signature purpose. The instrumented broker children recorded two calls for B, corresponding to the interrupted signing and its replay, and zero for A. The independent readback compares the two full provider inputs, A, B, the complete pre-Ready wire and the recovered wire. It also checks the four Witness attempt identities, both command identities and the fence/revision/digest tuples. The native observer authenticates the signed Witness replies before writing these public fields. ## Matched reservation disclosure

The paired local-only experiment copied the **closed synthetic** initiator and responder journal, wrapping key and journal ID to fresh private directories for each arm. The starting files were byte-identical, as were the session, authenticated offer and previous root. Both arms stopped after a durable intent and before it was applied or KEM computation started. The observer used the actual storage decoder on both rows. Normalizing the new response plan away reproduced the previous target-session payload byte for byte. Six honest messages completed in each branch. The witnessed trials use the original store and its independent live Witness. [Paired experiment](overlay/src/durable/messages/tests/stage4_matched.rs)

In the reference, the existing SDK parser admitted the 245-byte encapsulation field. In the candidate the authenticated control record ended at the public offer. At the original observer's fixed tail position the bytes were consequently the public offer suffix. The same SDK parser returned `InvalidPrivateKey` on that suffix in the measured cases. Separately, rerunning the unmodified reference disclosure experiments reconstructed six subsequent messages from each of the encapsulation and generation cuts. The candidate result identifies the missing input to that particular reconstruction. Its six honest deliveries are an interoperability and continuity check. They do not establish a general negative decryption result. [Original disclosure experiment](../../continuity-identity-candidate/RESERVATION_DISCLOSURE.md) · [Historical pending-image observation](../../sdk-alpha1/evidence/20261031-pending-image-disclosure/README.md)

The narrower exposure interval ends as soon as a readable phase-5 pending target contains the selected root. Reading the winning contribution in RAM, retaining access to later records under a compromised wrapping key, signing-owner compromise, physical erasure and power-loss persistence require separate evidence. Release after expiry still requires the original policy's authorization. Eliminating the 245-byte logical field gives no measured reduction in physical writes, syncs or Witness round trips.

## Reproduction

The recorded run used macOS arm64 and Rust 1.98.1. Of the 24 exact native test executions, four ran on the unmodified reference in Debug, ten on the candidate in Debug and the same ten in Release. They include the original on-disk signer restoration, every observed legacy responder sync-fault barrier in its existing test, the retained-reservation controls and the new process cases. The selected crate passed strict all-feature Clippy on its library, tests and KEM example. All 14 changed or added Rust paths passed rustfmt. Independent materialization checked the entire source inventory against Git and the overlay lock. Four altered public archives were rejected by the offline reader, covering the pre-Ready wire, provider input, Witness challenge and recorded token length. The first fixture setup failures, including private-directory admission, are retained separately. The hosted persistence study checks the retained model and both public archives, then rebuilds the reference and the prototype on Ubuntu and runs the native cases in Debug and Release.
