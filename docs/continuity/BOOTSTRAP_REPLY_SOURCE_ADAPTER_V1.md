## 3. Late family opening through adjacent ACK hybrids

Let `H_k` replace the first `k` protected class ACKs by independent keys in

`H_0` and `H_R` are U1's two schedule endpoints. Registration occurs before

`H_r,0 = H_(r-1)` and `H_r,1 = H_r`.

Let `J_r` be the original pair attached to the r-th registered class by
Lemma 2, or `bottom` if that registration never occurs. Use the same
available test bit `D` in every experiment. After the charged association

```text
E_Hr,0[D] - E_Hr,1[D]
  = sum_j ( E_Hr,0[D 1[J_r=j]] - E_Hr,1[D 1[J_r=j]] ).
```

**Lemma 3 — absence and opening certificates.** The `J_r = bottom` terms
cancel. For fixed `j`, before `J_r` has been set, opening a value that
reconstructs `p_j`'s seed or its eventual ACK is a free local stop for the
candidate bit `D 1[J_r=j]`. If `J_r` has already been set to `j`, the same
request is handled by U1's global pre-return recipe stop and retains the
test on the stopped prefix.

**Proof.** The adjacent machines perform exactly the same computation up to
the r-th registration: the only different assignment is that class's ACK
replacement. If registration never occurs, their full available executions
are identically distributed, proving cancellation of the `bottom` terms.

In the source profile, a prior `P_B`/seed opening reconstructs every future
ACK of that family from its eventual public transcript. So does a prior
selected `S1` opening, or a selected PQ generation/encapsulation source
opening together with the known first contribution and traditional material.
The cumulative recipe graph retains these observations. Every future
registration from `p_j` is therefore refused; no continuation can make
`J_r=j`. This holds even when a source is opened before its later
encapsulation or full transcript exists, because those future public bindings
complete the same deterministic recipe. A different pair at the r-th
registration likewise permanently excludes `J_r=j`.

After `J_r=j` has been registered, a corresponding source return triggers
the existing global stop. Its bytes are never required by the simulation.
That stop is not a local zero assignment: the existing prefix, quantum state
and any latched event are retained for `D`. **QED.**

The monitors inspect immutable provenance, public bindings and the U3
source/guard closure. They inspect neither a hidden tape value nor a quantum
oracle query. They are fixed before execution. A family opened before
protection continues with real algorithms in the original experiment and is
never promoted. Its *candidate reduction* can stop because that candidate's
event has become permanently impossible.

This is an event decomposition in the adjacent actual games. The different
candidate-local simulations are not asserted to be one common full-view
experiment, and no final family choice is moved back to an earlier challenge

## 4. The original ML-KEM challenge adapter

key, a prechallenge classical decapsulation oracle, one fresh encapsulation

decapsulation oracle excluding `c*`. Its adversary retains the experiment's
shared public oracles and all complete computation budgets.

Fix `r,j,b` before execution and run the full corresponding local controller.
The concrete adapter is:

1. At original reservation `g`, represent its 64-byte PQ key-generation
   input by an opaque original handle and sample the 32-byte traditional
   scalar locally. Bind the challenger's public key only to that original
   owner. At its first private generation use, publish that key with the
   local traditional public key. Other owners use locally generated tapes.
2. At reservation `a`, retain the immutable original peer/context binding.
   Its 32-byte PQ encapsulation input is opaque; its traditional scalar is
   locally sampled. At `a`'s first private encapsulation, verify that its
   original binding consumes `g`'s saved reply public key, request the
   challenge once, and cache the entire `(c*,K_ch)` result before any later
   persistence. An immutable contrary binding is a free candidate stop.
3. Recompute the traditional leg with its original scalar and public inputs.
   Form the complete ContextBound tuple using `K_ch` as the PQ component.
   Its original application context and both public keys/ciphertexts remain
   present. Exact retries reuse the same challenge and original tape handles.
4. Before challenge creation, route selected-owner decapsulation to the
   prechallenge oracle. Afterwards, a protocol decapsulation of `c*` under
   that owner receives the cached `K_ch`; every other PQ ciphertext uses
   the postchallenge oracle. Other owners retain their native local keys,
   even if public bytes coincide. The traditional leg and its rejection
   precede any resulting ContextBound call exactly as in the source.
5. Preserve scope, current-policy, owner, token and body checks. Handle
   expanded-owner restoration as in section 5. Original private payloads and
   copies are carried by the record interface in section 6. The pre-opening
   certificate handles their forbidden plaintext returns before the unknown
   bytes are required.

## 5. Fresh encapsulation collisions and owner validation

`restore_checkpoint` imports the saved expanded reply owner through
`expert::import_expanded`. That routine draws fresh 32-byte check coins.
`MlKem768::import_expanded_for_expert` computes a fresh encapsulation under
the embedded public key, decapsulates it under the restored owner, and checks
the expected and recovered shared secrets before returning the owner.

Maintain a cache of every other honest fresh encapsulation under the selected
PQ public-key bytes, including responder operations in other contexts and
expanded-owner consistency checks. Exact replay of `a` is not another fresh
encapsulation. Define `V_j` when one of these ciphertexts equals `c*`: check
the earlier cache at challenge creation and every later fresh ciphertext
before returning its result or performing the consistency decapsulation.
At `V_j` the local candidate score is zeroed. This is a charged local stop,
not a source error or an automatic validation success. It also prevents a
different honest encapsulation from carrying a locally known real key for
the selected challenge ciphertext into another ContextBound computation.

For a nonmatching selected-owner consistency check, the adapter performs the
public-key and fresh-encapsulation work normally and uses the permitted
decapsulation oracle; its native expected/recovered comparison remains
unchanged. Before challenge creation it uses the prechallenge oracle.

**Lemma 4 — fresh encapsulation collision bound.** Let `v_j` be a fixed
lifetime upper bound on all other relevant original fresh-`m` sampling
slots: same-PQ-public-key encapsulation reservation draws and fresh validation
draws, including unused, failed-retention and later selectively executed
reservations. This bounds, and can exceed, the number of cached ciphertexts.
With this budget, let
`delta_PKE,j(v_j+1)` bound a K-PKE decryption failure for the selected
challenge encapsulation or any of these other honest
encapsulations. Then

```text
Pr[V_j] <= nu_enc,j
        := min(1, v_j / 2^256 + delta_PKE,j(v_j+1)).
```

**Proof.** In ML-KEM encapsulation the 32-byte input `m` is encrypted by
K-PKE, with coins derived as specified by the encapsulation algorithm.
Before a K-PKE correctness failure, decrypting the challenge ciphertext
returns its original `m*`, and decrypting each other ciphertext returns its
original `m_i`. Equality of ciphertexts consequently implies `m_i=m*`. These
are distinct original uniform 32-byte sampling slots. For each pair, the
later of the two sampling events is independent uniform of the earlier
sample, even when the decision to allocate that slot depends on the earlier
view. Their equality probability is `2^-256`. Use the fixed lifetime slot
budget, including original samples reserved before their later computations;
a missing slot contributes no event. A union bound and the stated correctness
event prove the result. This covers both the prechallenge cache and later
validations/encapsulations without selecting a favorable fresh sample after
seeing its value.
This uses Algorithms 14, 15, 17 and 18 of FIPS 203; it does not assign a
numerical value to the K-PKE correctness term. **QED.**

Without this monitor, the random component could be compared to a locally
known validation key outside the ContextBound interface. The cost above
allows the actual restore check to remain in the source model while supplying
the raw-use premise of the hidden-input comparison. Prechallenge checks use
the ordinary prechallenge oracle; a past query that happens to equal the
later challenge retains its original earlier response.

## 6. Immutable record acquisitions and the constructible branch

For fixed `j`, mark every immutable record version whose private recipe
contains an opaque value required by any of the component/ContextBound/
entry/tail comparisons for that family. The marking uses a conservative
dependency closure: the selected original tapes and expanded owner,
selected component/ContextBound value, parent PRK/seed, and the family's
retained root or activation values when represented by private handles.
This includes their original operation tokens, containing images, pending
targets/intents and later source-preserving copies. Public fields such as
the Initial, Reply, confirmation tags and public fingerprints are available
outputs and are not opaque merely because their computation used a secret.

The closure is fixed by the proof's typed interfaces, not by which ciphertext
happens to be read later. A fresh image with one such retained payload is
marked; an atom-free image is constructible from known fields. A marked
immutable version stays marked after a later plaintext opening or live
deletion. Keeping the union over the relevant reduction stages ensures that
a root checkpoint is covered even when the original tape has been erased.

Let `C_j` be successful raw-byte acquisition of any marked opaque object.
This includes a directly acquired sealed operation and a pending intent that
contains the complete target ciphertext. It is independent of whether the
matching decryption key is currently known. In the local reduction, stop
before that raw return and set the candidate bit to zero. Define the exact
adjacent-endpoint residual

```text
eta_cap,r = sum_{b in {0,1}}
    Pr_Hr,b[J_r != bottom and C_(J_r)].
```

Each endpoint uses its own transcript, source attribution and acquisition
history. The mutually exclusive `J_r=j` events recover the sum over pairs
inside each endpoint. Capture after registration can depend on that endpoint's
ACK behavior, so it is not moved into a single original-real-game probability.

**Lemma 5 — local acquisition accounting.** For each `r,j,b`, changing the
candidate bit to zero on `C_j` changes its expectation by at most
`Pr_Hr,b[J_r=j and C_j]`. The free stops of Lemma 3 add no cost. The analogous
charged encapsulation-collision stop has cost at most `nu_enc,j`.

**Proof.** Before a local monitor fires the machine has the corresponding
actual endpoint's complete prefix distribution. Zeroing the bit on capture
can change it only on `J_r=j and C_j`. A free stop permanently excludes the
candidate event, so it changes no candidate bit. A validation stop changes a
bit by at most one on `V_j`; Lemma 4 bounds that event. Apply these arguments
to each adjacent endpoint separately. **QED.**

The remaining no-acquisition branch admits the existing constructive record
renderer. The hybrid order is essential: start with real component tapes and

For the exact image/intent specialization, a valid binary cost is

rho_rj,b = min(1,
    sum_{i=1..M_j} Phi_192(d_i, Q_i,rj,b)

## 7. Complete conditional schedule bound

For each `r,j,b`, let

```text
L_rj,b = rho_rj,b + a_rj,b + delta_j
       + Phi_256(d_j, Q_CB,rj,b)
       + Delta_entry,rj,b + D_tail,rj,b + chi_h(Q_h,rj,b).
```

The terms are respectively the concrete commitment/table comparison,
operational ML-KEM comparison, source correctness, complete-tuple comparison,
hidden-`S1` entry, one endpoint of the deferred conditional tail, and its
pad-alias collision monitor. The tail compares the two endpoint experiments
to the same full-table distribution, as proved in the terminal connection.
Here the r-th class is the distinguished ACK replacement; prior replacements,
other classes, source openings, registration ranks, candidate flags and all
latched events remain in the auxiliary controller and terminal bit.

**Theorem 6 — reply-source schedule connection.** For the profile above,
with the actual record acquisitions retained in the residual just defined,

```text
epsilon_schedule <= min(1,
  sum_{r=1..R} [
      alpha_r,0 + alpha_r,1 + eta_cap,r
    + sum_{j in [G] x [A]} sum_{b in {0,1}}
        (nu_enc,j + L_rj,b)
  ]).
```

Thus uniform valid bounds give the explicit conservative resource shape

```text
epsilon_schedule <= min(1,
    2 R alpha + sum_r eta_cap,r
  + 2 R G A (nu_enc + rho + a + delta
             + Phi_256(d,Q_CB) + Delta_entry + D_tail + chi_h(Q_h))).
```

No factor is hidden in a target-guessing convention. The concrete sum may
skip impossible pair bindings and never-executed slots, while the displayed
uniform expression is a valid fixed-budget bound.

**Proof.** Telescope the adjacent ACK hybrids. Charge the association monitors
in their two endpoint distributions. Lemma 3 cancels the absent-registration
terms and decomposes the remaining difference into fixed-pair candidate bits.
Lemma 5 supplies the exact capture residual and encapsulation-collision costs.

For each local endpoint, apply the constructible record comparison while
the original tapes are still known. Install the component adapter of section
4, apply the complete-tuple comparison, and assign its distinguished table
entry to the hidden-`S1` service at the original response computation. The
entry comparison supplies the opaque PRK family. Apply the corresponding
endpoint of the terminal schedule connection, retaining its actual class
aliases and extra pad monitor. Lemmas 1–3 ensure that all selected source
uses and opening decisions remain implementable at the required points.

The two resulting full-table local experiments couple with the same candidate
bit code `D 1[J_r=j]`. In that coupling the replaced r-th ACK is the same
fresh class value, and all other outputs, family attribution, registration
flags, stops and continuations have the same distribution. Their candidate
expectations are equal. The triangle inequality bounds each pair by the two
`L` costs; summing the finite candidates and ranks gives the theorem. **QED.**

Substitution in U1 is now concrete for this reply-source profile:

```text
Pr[latched Bad] <= min(1,
    Pr_real[Coll] + epsilon_schedule + epsilon_mac
  + q_v / (2^256 - q_v + 1)).
```

In the branch admitting no successful raw acquisition of the marked opaque
